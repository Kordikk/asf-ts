# SDK compatibility and accounting qualification

## Verified offline

Environment: Node 22.22.3, npm 10.9.8, Linux. Runtime dependencies are pinned:

- `@openai/codex-sdk@0.154.0`, expected `codex-cli 0.154.0`.
- `@opencode-ai/client@0.0.0-beta-18684`, expected `opencode2 v0.0.0-beta-18684`.
- Ajv 8.20.0 for trusted draft-07 schemas.

The exact `@opencode-ai/sdk@0.0.0-beta-18684` package was installed and inspected first. Its embedded API is `OpenCode.create`, `sessions`, `events`, `close`/async disposal, **not** stable 1.x `createOpencode`. Plain Node import failed on extensionless `dist/opencode`; with tsx it failed on the published server import `handlers/index.jsx`. An embedded host also starts suspended-session recovery. The unusable embedded package was removed from runtime dependencies (498 unnecessary transitive packages removed). No package patching or Python bridge is used.

The exact beta stores credentials in SQLite, not in a separately shared `auth.json` file. Therefore the owned `OPENCODE_DB`/private configuration intentionally excludes an ordinary native login. An explicit, provider-bound API-key handoff uses the official `integration.connect.key` endpoint to seed only a newly owned DB, after policy readiness and before model selection. Key values are excluded from ASF identity/argv/inline config, and handoff exceptions withhold native details. Reopening a continuation does not re-provision or import global credentials. The optional no-model lifecycle test exercises this with a synthetic Go key and verifies persistence across restart; it does not validate entitlement or send a provider prompt.

The same-release **official HTTP client** loads directly on Node. Its typed `OpenCode.make` API talks to an owned CLI `serve --stdio --hostname 127.0.0.1 --port 0` server. The single JSON URL handshake is a documented server startup protocol, not a harness transcript parser. ASF supplies a random Basic-auth password, uses only loopback, a unique private native DB per initial session, private configuration and a checked no-retry plugin. It never calls global service discovery/start/stop. Readiness polling is non-model metadata, not prompt retry.

The opt-in **offline** installed-CLI test has been run successfully: empty temporary HOME/XDG roots, server startup/health version via the official client, actual policy-plugin activation, private native database creation, process-group cleanup. A private metadata-only session was created/renamed/read/interrupted to verify log/wait APIs; no model/session prompt was sent. Plugin list can initially be empty while the beta supervisor initializes; ASF waits for its policy's active status with a finite deadline. Shared adapter tests inject the exact typed SDK interfaces; a separate fake executable test uses the real Codex SDK/launcher/parser. CI has no installed native CLI requirement or provider credentials.

The Codex configuration regression test captures the actual SDK/launcher-generated argv without invoking a model. Opt in to native validation with `ASF_TEST_CODEX="$(command -v codex)" npx tsx --test test/codex-config.test.ts`. This passed against `codex-cli 0.154.0`: an isolated app-server accepts those same config flags and responds to `initialize` and `config/read`; restoring the removed `model_providers.openai` retry overrides fails startup with the reserved-built-in-provider error. Only metadata requests are sent, with an allowlisted environment and temporary HOME/CODEX_HOME/XDG roots, no inherited credentials or private sessions. No thread/turn is created. This validates configuration compatibility, not model behavior or native retry suppression.

## Accounting matrix

| Adapter       | Usable path                                                                                                                                                                                     | Failure/coverage boundary                                                                                                                                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex         | Cumulative `turn.completed.usage` minus ASF-owned prior baseline, explicit requested-model rates                                                                                                | Structured actual-model attribution absent; visible textual reroute notices fail closed. Unknown subagent scope or missing terminal usage also fails closed. Requested-model estimate only, not verified actual-model billing.            |
| OpenCode beta | Public-feed `session.step.started` model paired with `session.step.ended`/`failed` tokens, deduplicated by sequence, explicit matching-model rates; compare sum against session aggregate delta | Missing/zero normalized usage, reroutes, missing steps, aggregate mismatch, native failure/retry => incomplete. Auxiliary title/compaction usage retains native estimate but lacks model provenance, so incomplete and blocks more sends. |

**Codex details.** This release's SDK declaration describes usage “during a turn,” but the version's core terminal event emits cumulative thread totals (parent source verification). Input includes cache read/write; ASF subtracts these categories into exclusive inputs and differences every category against its durable baseline. Output already includes reasoning. Negative deltas, all-zero dispatch usage or conflicting duplicate terminal usage are not accepted. Multi-agent is disabled and the built-in OpenAI provider is explicit. CLI 0.154.0 rejects `model_providers.openai` overrides, including request/stream retry limits. ASF does not retry failed/uncertain dispatches, but Codex request/stream retries remain vendor-controlled and may occur within one ASF dispatch. Native retry suppression is not claimed. Native tool calls may still access external services; their unreported charges and any invisible vendor work are outside the scope. Structured actual-model attribution is absent, but v0.154 can emit an `error` item with `model rerouted: requested -> other`. ASF retains the bounded notice independently of content tracing and fails accounting closed, preventing structured correction and subsequent paid dispatch. Reported tokens and their requested-rate estimate remain an incomplete known subtotal, not an invented actual-model price. No actual model ID can be invented from the requested model.

**Codex signal lifetime.** The exact SDK's `CodexExec.run` disposes its iterator with `child.removeAllListeners()` and `child.kill()`. A report-sink failure followed by Runtime's abort could then emit an unhandled `AbortError` into that disposed child, and a second termination signal could interrupt shim cleanup. The adapter now passes an invocation-owned signal and detaches its upstream cancellation listener on iterator disposal. Active cancellation still reaches the SDK; accounting failures still fail closed with known reports retained. A real-SDK/synthetic-executable regression fails before the fix and passes afterward, including cleanup of a TERM-ignoring native fixture. No vendor package is patched and no exception is globally swallowed.

**OpenCode details.** `SessionStepEnded` itself has **no model** in this exact release. ASF joins the preceding `SessionStepStarted` model and obtains final text from the assistant message API, not tool narration. The public `event.subscribe` stream is durably recorded by ASF. **The CLI defaults `Bus.persist` to false and exposes no CLI option to enable it**: `session.log` cannot return event data even with `follow=true`; a non-follow read returns only `log.synced` with a sequence watermark. An actual isolated rename/log test confirmed this. ASF establishes its public event subscription and awaits `server.connected` before prompt, requires contiguous live sequences, waits until that stream reaches the post-wait watermark, and rejects gaps/disconnection rather than pretending to replay missing usage. The native assistant-message API and aggregate provide final text and a usage cross-check; they do not repair missing live evidence. That same SDK transport supplies text/reasoning deltas and tool progress, routed to a separate lossy trace path. Mandatory accounting is processed regardless of trace settings. The native public feed has a 4,096-event buffer and disconnects on overflow; ASF fails accounting closed on disconnection. `session.wait`, `session.get`, `message.list`, `session.interrupt`, `session.log` and the no-retry hook are source-confirmed interfaces, not 1.x assumptions.

Tool evidence also requires exact-version semantics: `SessionEvent.Tool.Success.executed` is the publisher's **providerExecuted** flag, not a generic success flag. `session/runner/publish-llm-event.ts` publishes successful local `toolExecution` with `executed:false`. Match the success event and call ID/name/input; do not reject local tool success because that flag is false. `scripts/qualification-evidence.ts` and its regression encode this distinction.

Core `SessionUsage.tokens()` maps missing values to zero. Its output is **visible** output, with reasoning separate; ASF adds reasoning once to its inclusive-output convention. Core `calculateCost()` returns zero if no cost tier exists. Therefore ASF does not use a zero native estimate as evidence of reliable free/billed work. Explicit user rates avoid missing catalog prices; positive normalized token totals provide a scoped estimate, but cannot prove each normalized zero was truly reported. This unavoidable component-coverage limitation is excluded in every successful record. Actual model must match the supplied rate key. Tiered/context-dependent pricing is not automatically modeled: supply suitable explicit rates and treat the result as an estimate.

Main-step reports are cumulative snapshots, not summable observations. A final receipt alone enters the ledger. A failed step with a positive native cost but no tokens immediately records that cost as a separate `harness-estimated` component, with bounded failure metadata and incomplete coverage. Its missing token-priced primary remains null unless other steps supplied usable tokens. This survives a later disconnect and is not added again as an aggregate residual. Auxiliary `session.usage.recorded` is not in this beta public event union. Its sequence gap/aggregate usage discrepancy makes the invocation incomplete. A positive session aggregate cost residual after subtracting observed native step costs is retained as a separately classified, unattributed native estimate with null model; it is not added as a duplicate session total. If a supported event source provides explicit auxiliary usage, that observation is retained similarly. Any such auxiliary observation is currently an **in-scope qualification blocker for successful accounting**, while preserving known usage/cost. Session aggregate is a reconciliation check, never an amount added a second time. Explicit session titles, disabled title/compaction agents, and `compaction.auto=false` reduce auxiliary activity but do not establish full coverage. Late/unreported auxiliary work may remain invisible; native continuation rechecks its aggregate baseline.

Both adapters preserve usable usage when a later error/reset loses fields. Raw receipts persist before typed parsing. Provider errors never trigger another model call for accounting. Successful invoice/full-provider-cost coverage is **not claimed**, and no adapter labels local estimates as billed spend.
